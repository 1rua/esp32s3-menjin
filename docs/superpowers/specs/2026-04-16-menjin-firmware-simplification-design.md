# 2026-04-16 门禁固件精简设计

## 背景
当前固件主要集中在 `esp32-s3-menjin-version3.0/menjin_esp32s3___official_version3.0.ino` 单文件中，既包含核心门禁能力，也混杂了天气获取、灯控舵机、离家/回家模式、持久开门等场景化功能。本次目标是在不影响核心门锁舵机功能的前提下，对外围场景功能进行裁剪，并顺手整理门锁主链路。

## 目标
将固件收敛为“去场景化的核心门禁版本”，保留以下能力：
- 门锁舵机开/关
- NFC 解锁
- 指纹解锁与录入
- 键盘密码解锁
- MQTT 远程开门
- Web 开门
- Web 管理：WiFi 配网、NFC 白名单写入
- OTA
- WiFi / NVS

明确删除以下能力：
- 天气获取与天气状态
- 灯光舵机控制
- 离家模式 / 回家模式
- 持久开门（keep open）
- 与以上能力关联的配置、状态变量、函数、Web 控件、MQTT 分支与触发逻辑

## 设计原则
1. 不做拆文件重构，继续在现有单文件结构内完成裁剪。
2. 以“删除外围功能、保住核心门锁链路”为最高优先级。
3. 顺手整理门锁主链路，但避免超出需求的大范围重构。
4. 所有解锁入口最终汇聚到统一的授权开门逻辑，避免开门动作散落在不同场景函数中。

## 方案选择
采用“方案 B：功能裁剪 + 顺手整理门锁主链路”。

该方案在删除天气、灯控、离家/回家模式与持久开门功能的同时，将现有偏场景化的开门封装收敛为更纯粹的门禁主链路，使 Web、MQTT、NFC、指纹、键盘等入口统一调用门锁开关逻辑。

## 保留范围
### 本地入口
- NFC 验证成功后开门
- 指纹验证成功后开门
- 键盘密码正确后开门

### 远程入口
- MQTT 普通开门命令
- Web 普通开门按钮

### 管理与维护
- Web 的 WiFi 配网接口
- Web 的 NFC 白名单写入接口
- OTA 更新
- WiFi / NVS 初始化与持久化

## 删除范围
### 1. 天气相关
删除：
- 天气 API 配置项
- 天气状态变量
- `updateWeather()` 及其调用点
- 仅为天气服务的依赖（若无其他用途）
- 天气联动判断逻辑

### 2. 灯控相关
删除：
- 灯控引脚定义
- 灯控舵机对象
- `physicallySwitchLight(...)`
- 灯控状态变量
- 灯控相关调用点

### 3. 离家 / 回家模式
删除：
- `triggerLeaveHome()`
- 当前“回家模式”封装函数及其场景语义
- 触摸触发离家逻辑
- 与回家/离家模式耦合的附带动作

### 4. 持久开门
删除：
- keep-open 相关主题、常量、参数范围
- Web `/keep` handler
- HTML 中持久开门区域与前端脚本
- MQTT 中 keep-open 分支
- 任何长时开门模式逻辑

## 代码整理方式
### 1. 收缩配置区
顶部配置仅保留：
- WiFi / MQTT / OTA
- 门锁舵机参数
- 键盘密码
- NFC 相关限制
- Web / NVS 必需项

删除天气配置、灯控引脚、触摸引脚和场景模式常量。

### 2. 收缩全局状态
全局状态仅保留门锁、联网、NFC、键盘、OTA 所需变量。
删除天气缓存、灯控状态、场景状态和持久开门状态。

### 3. 整理门锁主链路
保留：
- `openDoor()`：只负责门锁舵机动作
- `closeDoor()`：只负责门锁舵机动作

新增或收敛一个统一的“授权开门”入口，负责：
- 接收开门来源（NFC / 指纹 / 键盘 / MQTT / Web）
- 设置标准开门持续时间
- 调用 `openDoor()`
- 标记门已打开并交给主循环按时自动关门

目标是让所有成功入口汇聚到同一条门锁主链路，不再依赖回家/离家之类的场景函数。

### 4. 收缩 Web 界面
网页仅保留三块能力：
- 开门
- NFC 白名单写入
- WiFi 配网

删除持久开门的输入框、按钮、前端脚本与对应后端接口。

## 预期行为
精简后，系统的核心行为应为：
1. 某个本地或远程入口认证/命令成功；
2. 统一授权开门逻辑被调用；
3. 门锁舵机执行开门动作；
4. 经过标准时长后自动关门。

所有保留入口都必须复用这条主链路。

## 验证策略
### 1. 编译完整性
- 删除后的函数声明、定义、调用保持一致
- 不留下悬空变量、未使用依赖、失效路由

### 2. 门锁主链路正确性
- 所有保留入口都仍然能走到统一开门逻辑
- `openDoor()` / `closeDoor()` 不再依赖场景化函数

### 3. Web 管理能力完整性
- `/open`、`/add_nfc`、`/set_wifi` 仍然存在
- 前端页面与后端 handler 一一对应

### 4. MQTT 普通开门能力
- 普通开门命令仍可触发门锁
- 删除 keep-open 后不影响普通开门主题

## 非目标
本次不做以下工作：
- 不拆分成多文件架构
- 不引入新的抽象层或框架
- 不改变现有指纹、NFC、键盘的业务规则
- 不新增功能或扩展管理页面

## 实施结果判定
若实现后满足以下条件，则认为本次精简成功：
- 编译通过
- 核心门锁舵机开/关行为未受影响
- NFC、指纹、键盘、MQTT、Web 五类入口仍可触发开门
- Web 管理能力仍保留 WiFi 配网与 NFC 白名单写入
- 天气、灯控、离家/回家模式、持久开门相关代码已被彻底移除
